# Commons on phones and computers

Commons runs on iPhone, Android, Mac and Windows. There are two routes to that,
and they are not equally finished. This page is explicit about which is which,
because "we have an app" is easy to say and expensive to be wrong about.

| Route | iPhone | Android | Mac | Windows | State |
|---|---|---|---|---|---|
| **Install from the browser** (PWA) | yes | yes | yes | yes | **Working and verified** |
| **App Store / Play Store** (Capacitor) | scaffolded | scaffolded | — | — | **Not built, not tested** |
| **Desktop app** (Electron) | — | — | scaffolded | scaffolded | **Not built, not tested** |

---

## 1. Install from the browser — this works today

Commons is a progressive web app. Anyone can install it from its web address
and get a real app: an icon on the home screen or dock, its own window with no
browser chrome, and an app that still opens with no signal.

**iPhone / iPad** — open Commons in Safari, tap Share, then *Add to Home
Screen*. Safari is the only browser on iOS that can install a web app.

**Android** — open it in Chrome. A prompt appears on its own; otherwise use the
menu and *Install app*.

**Mac / Windows** — open it in Chrome or Edge and use the install button in the
address bar.

What that gets you:

- The Commons icon, drawn by `npm run icons` (see `scripts/make-icons.mjs` —
  the icons are generated from source, not committed as mystery binaries).
- A standalone window with no address bar.
- Instant opens, because the shell is cached.
- A page that explains itself when the connection is gone, rather than a
  browser error.
- Three shortcuts from a long-press or right-click on the icon: Ask for help,
  Get-togethers, People.

What it deliberately does **not** cache: anything under `/api/`. Posts, people
and messages always come from the network. Showing yesterday's community as if
it were today's would be worse than showing an error.

Requirements in production: it must be served over **HTTPS** (localhost is
exempt). Without that, no browser will offer to install it.

### Files

```
public/manifest.webmanifest   name, colours, icons, shortcuts
public/sw.js                  the service worker — shell cache only
public/offline.html           shown when there is no connection at all
public/icons/                 generated by `npm run icons`
scripts/make-icons.mjs        draws the icons with node's zlib, no dependencies
```

**When you change `commons.js` or `commons.css`, bump `SHELL_VERSION` in
`public/sw.js`.** Returning members keep the old cached file until you do.

## 2. App Store and Play Store — scaffolded, not built

`capacitor.config.json` is written and points at a server you set. Turning it
into store-ready apps needs a Mac with Xcode (for iOS) and Android Studio, and
neither exists in the container this was developed in, so **none of the
following has been run**:

```bash
npm install --save-dev @capacitor/cli @capacitor/core @capacitor/ios @capacitor/android
# point capacitor.config.json at your real server first
npx cap add ios
npx cap add android
npx cap sync
npx cap open ios        # needs Xcode
npx cap open android    # needs Android Studio
```

Before submitting to either store you still need: a paid developer account
(Apple $99/year, Google $25 once), signing certificates, a privacy policy URL,
store screenshots, and an age rating. Apple in particular rejects apps that are
only a website in a wrapper, so the app needs to justify itself with something
native — push notifications for a reply to your question would be the obvious
candidate, and it does not exist yet.

## 3. Mac and Windows desktop — scaffolded, not built

`desktop/main.js` is an Electron shell. Its one real design decision: **it is a
window onto a shared server, not a copy of one.** Running the Commons server
inside the desktop app would give every person their own empty private
community, which is the opposite of the point. So on first run it asks which
Commons to open, remembers it, and goes straight there afterwards.

It is written with `nodeIntegration: false`, `contextIsolation: true` and
`sandbox: true`, and off-site links open in the real browser rather than inside
the app.

**Not run.** There is no Electron binary, no Mac and no Windows machine here.

```bash
npm install --save-dev electron electron-builder
npm run desktop                        # run it locally
npx electron-builder --mac --win       # needs a Mac to produce a signed .app
```

Shipping it for real also needs code signing (an Apple Developer ID, a Windows
Authenticode certificate) or both operating systems will warn people off
opening it.

---

## What to do first

If the goal is people using Commons, **ship the web app over HTTPS and tell
people to install it from the browser.** It is finished, it works on all four
platforms, and it costs nothing per year. The stores are worth the money and
the ceremony only once there is a community big enough that being findable in a
store matters.
